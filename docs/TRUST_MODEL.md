# Trust model

Phase 1 trusts the downloaded Parquet bytes identified by SHA-256, the recorded USD conversion, application status snapshot, and a specific graph configuration. SHA-256 checks integrity of the downloaded snapshot against the pinned digest; it does not authenticate Gitcoin as the publisher or validate every event. The Phase 0B Arbitrum receipt comparison covered one event only.

No matching mechanism infers identity from wallet addresses. Co-donating, concentrated support, Shapley share, or centrality are descriptive signals. An organic community may look identical to a controlled group in the observed data. Any future harm or false-positive claim must use a labeled synthetic control or an independently verified sample.

Phase 3's Merkle root commits to a payout table selected by the contract owner. On-chain verification establishes that a claim belongs to that committed table, binds schema version, chain ID, vault, native asset, round, grant, recipient and amount, and prevents a second claim for the same grant in that round. It does not prove that the downloaded data, graph construction, `soft_base` allocation, recipient map, or root publication was correct. The publisher could commit an arbitrary but internally consistent table. Independent review requires the pinned input SHA-256, frozen configuration, algorithm version, full payout manifest, bundle and reproducible computations. The `data_sha256` and `config_sha256` fields are off-chain provenance metadata; the contract does not verify them.

The owner has exclusive authority to publish and fund an immutable round and chooses its claim deadline. The contract does not independently enforce `sum(leaves) <= poolFunded` when a root is published; it checks the remaining funded balance on each claim. The owner can sweep unclaimed funds after the deadline. These are governance assumptions of the local prototype, not guarantees supplied by a Merkle proof. Any caller can submit a valid claim, and funds go only to the nonzero recipient bound in the leaf. The native ETH test recipients are deterministic checksum addresses derived from project IDs; they are local test artifacts and are not asserted to be spendable by project owners. The 100 ETH test pool is independent of the Phase 2 USD research pool. It is a proportional demonstration, not a currency conversion.

The contract uses OpenZeppelin proof verification, ownership and reentrancy protection, and commits one root per round. It stores `claimed` state for each successful grant, so total on-chain storage still grows with the number of claims. Failure of a recipient's ETH transfer reverts the claim state. The benchmark measures `receipt.gasUsed` on a local Hardhat EVM with Cancun and fixed compiler settings; these gas units do not imply a mainnet transaction price or USD cost. The naive contract is a comparison implementation, not a production vault. Neither contract has undergone an independent audit.
